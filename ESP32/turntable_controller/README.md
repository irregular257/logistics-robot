# 外置供料转盘：ESP32-S3、A4988、42 步进电机与 ESP-NOW

这份实现控制外置供料转盘，与小车上原有的三槽储料舵机转盘分开。识别沿用现有 K230 → STM32 → 小车 ESP32 链路；网页设置三件物料的颜色、形状和抓取顺序。外置转盘由另一块 ESP32-S3 通过 A4988 驱动 42 步进电机。STM32 判断目标是否匹配，转盘通信不传物料颜色、形状或识别坐标。

## 两秒是否足够

**识别结果已经产生后，正常工作的近距离串口和 ESP-NOW 通信通常远小于两秒；完整识别窗口是否足够，要测 K230 的实际推理帧率和完整链路。当前没有实机时延数据，不能保证两秒一定够。**

转盘在两秒识别窗口中已经停止。HOLD 的含义是保持停止、不进入下一次 60° 转动。锁定成功后，停留时间由抓取完成事件决定，可以超过两秒。两秒不是整个抓取动作的时间限制。

现有工程的实测前已知条件：

| 环节 | 代码配置或理论值 |
|---|---|
| K230 视觉确认 | 连续 3 帧；实际 FPS 尚未测量 |
| K230 结果发送 | 最快每 50ms 一次，仍受推理帧率限制 |
| K230 → STM32 | 16 字节、115200 8N1，线上约 1.39ms |
| STM32 自动控制检查 | 70ms 周期 |
| 新增 STM32 ↔ ESP32 转盘消息 | 50ms 周期，沿用原 CRC16 UART 协议 |
| ESP-NOW 命令 | 同一序号每 40ms 重试，600ms 内未获应用层确认即故障 |
| 转盘状态 / 心跳 | 状态 50ms；心跳 100ms；失联 600ms 停止并故障 |
| 转盘机械稳定等待 | 默认 200ms，结束后才开始两秒窗口 |

例如 10 FPS 时，为连续三帧保守预留约 300ms，再预留图像缓存、各级调度、通信重试及余量，完整识别锁定可以先按约 0.8～1.2 秒做设计预算。这是示例预算，不是这套硬件的测试结果。2 FPS 时，三帧本身就应预留约 1.5 秒，剩余时间可能不足。

原自动流程需要连续五份居中报告才下降抓取。新流程在首份经过 K230 三帧确认、属性匹配的新鲜结果出现时就请求 HOLD，收到 HELD 后再执行原有的对齐及五次居中确认，因此对齐耗时不占用两秒识别窗口。

联调时应记录“转盘 READY → K230 有效报告 → STM32 HOLD → 转盘 HELD → STM32 收到 HELD”各时间点，可用串口抓包或逻辑分析仪。两板 millis() 未同步，不能直接相减。以同一设备/采集时钟测量端到端时间，覆盖网页同时访问、不同光照及无线丢包场景。建议从 2 秒开始，若最慢样本接近窗口末尾，改为 3 秒；不要把无线时延当作有确定上界。

## 工作流程

1. 转盘上电不转动。人工将一个料位对准识别/抓取位置，通过转盘 USB 串口发送 `A` 确认基准。
2. 小车接受网页启动命令后，通过 STM32 发起外置转盘任务。首先识别当前基准料位；此后每次前进 60°。
3. 转盘完成运动，等待 200ms，再发布带窗口号的 READY。只有 READY 状态开放 2000ms 识别时间。
4. 每个新窗口，STM32 向 K230 重新选择目标并更换请求 token，K230 清空跟踪确认计数。旧窗口、旧 token 的结果不能触发抓取。
5. 首个有效目标触发 `HOLD(本次任务, 本窗口)`。转盘在窗口内接受后进入 HELD，返回应用层执行确认。小车收到同任务、同窗口、同启动会话的 HELD 后才允许对齐、下降和抓取。
6. 转盘在 HELD 中持续保持使能和保持力。小车把物料存入车载料盘、升降回到安全位置后发送 PICK_DONE。收到执行确认后才开始下一件。
7. 前两件 PICK_DONE 触发下一次 60° 转动；第三件进入 DONE 并保持停止。小车继续原来的三件投放流程。

两秒到期后才到达的 HOLD 会被拒绝，小车回到等待下一窗口，不会在下一段运动中途把“停止”误判为可抓取。重复 HOLD/PICK_DONE 使用同一序号；丢包重发不重复取料计数。

转盘或小车 ESP32 重启、状态过期、心跳丢失、窗口异常、60 秒内未完成一次锁定取料等情况都会禁止抓取或停止转盘。故障不会超时自动恢复转动；确认机构安全、重新对位并发送 `A`，再重新发起任务。转盘 USB 串口 `X` 可停止并进入故障。软件停止不能代替硬件急停。

## 接线与电机参数

已确认驱动器为 **A4988**。现有 STEP/DIR 脉冲控制可以直接沿用，EN 为低电平使能。“42 步进电机”只说明安装尺寸，步距角和额定相电流仍需查电机铭牌。以下为常见 A4988 小模块按端子名称的接法，实物正反面、插针方向和板上标注需要核对。

| A4988 端子 | 连接 |
|---|---|
| STEP | ESP32-S3 GPIO4 |
| DIR | ESP32-S3 GPIO5 |
| ENABLE / EN | ESP32-S3 GPIO6，低电平使能 |
| VDD | ESP32-S3 3.3V，逻辑电源 |
| 逻辑 GND | ESP32-S3 GND |
| RESET / RST、SLEEP / SLP | 两脚相连后接 VDD（3.3V），保持高电平 |
| MS1、MS2、MS3 | 当前默认 1/16 细分：全部接 VDD（3.3V） |
| VMOT | 独立电机电源正极，例如满足电流要求的 12V 电源 |
| VMOT 旁的 GND | 电机电源负极，并与 ESP32-S3 GND 共地 |
| 1A、1B | 电机同一相的一对线 |
| 2A、2B | 电机另一相的一对线 |

A4988 的逻辑 VDD 范围为 3～5.5V。这里明确使用 3.3V，以匹配 ESP32 GPIO；VDD=5V 时，3.3V GPIO 不满足数据手册给出的高电平最小值 0.7×VDD，不能保证可靠识别。VMOT 的芯片工作范围为 8～35V，实际还受模块电容及供电额定值限制，不能用 ESP32 的 3.3V 引脚给 VMOT 供电。依据 [Allegro A4988 数据手册](https://www.allegromicro.com/-/media/files/datasheets/a4988-datasheet.pdf)。

VMOT 与其 GND 附近放置电解电容（至少 47µF，可用 100µF，耐压相对电源电压留余量），减小电源线引起的尖峰；电机接线应断电操作，不能带电拔插。RESET 不能悬空，SLEEP 应保持高电平；如果今后用 GPIO 控制 SLEEP，从休眠唤醒后至少等待 1ms 才能发送 STEP。模块接线及电源去耦参考 [Pololu A4988 模块说明](https://www.pololu.com/product/1182)。

### 细分与每次 60° 的脉冲数

程序默认：`MOTOR_FULL_STEPS=200`（1.8°）、`MICROSTEPS=16`、减速比 `GEAR_NUMERATOR/GEAR_DENOMINATOR=1/1`。A4988 通过 MS1/MS2/MS3 电平设置细分，当前代码不占用 GPIO 控制它们，因此必须在硬件接线/跳帽上设置：

| MS1 | MS2 | MS3 | 细分 | 代码 MICROSTEPS |
|---|---|---|---|---|
| 低 | 低 | 低 | 整步 | 1 |
| 高 | 低 | 低 | 1/2 | 2 |
| 低 | 高 | 低 | 1/4 | 4 |
| 高 | 高 | 低 | 1/8 | 8 |
| 高 | 高 | 高 | 1/16，当前默认 | 16 |

高电平接 VDD=3.3V，低电平接 GND。MS 引脚悬空时内部下拉使其为整步，不会因为代码写了 `MICROSTEPS=16` 就自动变为 16 细分；硬件和代码不一致会使转动角度错误。若是 0.9° 电机，`MOTOR_FULL_STEPS` 改为 400。每输出轴一圈脉冲数为：

```text
P = 每圈整步数 × 细分 × 减速比
每次60°的理想脉冲数 = P / 6
```

默认 P=3200，不能每次简单取 533。代码用累计位置取整，六段为 533、534、533、533、534、533，总计 3200，避免取整误差累积。细分角度存在实际误差，开环步进也可能丢步；当前“到位”来自完成脉冲计数和稳定等待，没有编码器或原点开关验证。每次上电必须人工对位，正式运行建议加原点传感器及位置反馈。

当前 STEP 正常高、低电平间隔至少 100µs，超过 A4988 要求的 1µs；DIR 在运动前设置并保持不变。停止时停止 STEP 脉冲，ENABLE 继续保持低电平，保留保持力；不能通过拉高 ENABLE 来代替抓取期间的锁定。

### 电流限制

按电机额定相电流和模块散热能力设置限流，再空载试转。A4988 的峰值限流关系为 `Imax = Vref / (8 × Rsense)`。Rsense 取决于实际模块，例如 R100 为 0.10Ω、R050 为 0.05Ω；同样设置 1A 峰值限流，对应的 Vref 分别为 0.8V、0.4V。这只是公式示例，并非给当前电机推荐固定电流。不要给所有 A4988 模块统一套用一个 Vref，也不能把电源输入电流当作线圈相电流。持续保持停止也会发热，需要核对电机和驱动板温升及散热。

K230、STM32 与小车 ESP32 的原接线保持现有定义：K230 IO32 TX → STM32 PC7，IO33 RX ← PC6；小车 ESP32 IO17 TX → STM32 PA1，IO16 RX ← PA0；115200 8N1、3.3V UART、共地。无线两端无需通过线缆共地。

## 配置与启用

代码默认关闭小车侧新功能，避免尚未填写 MAC 时影响原工程。完成以下配置再配套编译烧录 STM32 和两块 ESP32。

1. 把 `ESP32/libraries/TurntableNow` 整个目录安装到 Arduino 草图本的 `libraries/TurntableNow`，或 CLI 编译时指定 `--libraries`。仅打开 `.ino` 而未安装共用库，会找不到头文件。
2. 在 `robot_WebControl/table_bridge.h` 将 `TABLE_NOW_ENABLED` 改为 `1`，在 `Core/Inc/logistics_config.h` 将 `LOG_EXTERNAL_TABLE_ENABLED` 改为 `1`。
3. 两端上电查看串口打印的 **STA MAC**。转盘程序的 `CAR_MAC` 填小车的 STA MAC；小车 `TABLE_NOW_PEER_MAC_BYTES` 填转盘的 STA MAC。全零占位符会让初始化失败并禁止自动抓取；初次读取 MAC 后应重新编译配置好的程序。
4. 两端使用信道 `1`。小车启用功能后自动改为 `WIFI_AP_STA`，保留 `Robot-Car` 网页热点；STA 接口用于 ESP-NOW。不要填 AP/BSSID MAC，也不要在运行时连接不同信道的路由器或扫描切换信道。
5. A4988 按上表连接；默认引脚 GPIO4/5/6、EN 低电平有效、16 细分（MS1/MS2/MS3 全高）。按电机铭牌和机构确认步距角、方向、减速比及电流限制；实际细分与 `MICROSTEPS` 保持一致。
6. 烧录后先空载测试：人工对位并给转盘串口发送 `A`，再由小车网页设置三件计划、确认初始机械位置并启动。检查每次旋转、锁定、延迟/丢包及三件停止，再装物料验证。

复位或重新对位会更换转盘启动 ID，运行中的小车会终止原任务；重新对位应在任务停止、夹爪退离后进行。STM32/ESP32 两边的开关必须配套启用；仅启用一端会导致等待或故障。

USB 串口无需固定波特率之外的额外命令格式，监视器设 115200，发送单个 `A` 或 `X` 即可；换行会忽略。ESP32-S3 N16R8 的 Arduino 菜单沿用工程主 README 的设置。

## 协议与核验

ESP-NOW 使用固定对端 STA MAC 的单播包，当前未启用链路加密。36 字节包包含版本、双方启动/运行 ID、命令序号、窗口号、状态、取料计数、应用层 ACK 和结果码。应用层确认表示状态机已经执行；无线发送回调只释放发送通道，不能授权机械臂抓取。

STM32 → ESP32 新增 `0x82`、9 字节请求；ESP32 → STM32 新增 `0x0F`、15 字节状态，沿用原串口帧版本、会话和 CRC16。旧的网页命令和32字节状态布局保持兼容。具体字段见两端 `web_protocol.h`。

核验入口：

```text
tests/turntable_review/build_state.cmd       无线状态机、窗口边界、重发计数、复位、超时及脉冲累计
tests/turntable_bridge/build_bridge.cmd     小车桥接、应用ACK门控、过期排队包、重试与失联
tests/table_review/build_table.cmd          启用功能的STM32实际物流状态机和串口收发
tests/build_logistics.cmd                   默认关闭新功能时的原物流回归
tests/rtos_review/build_runtime.cmd         RTOS请求队列和电机总线并发回归
```
